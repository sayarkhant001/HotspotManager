[2026-09-30 09:45] Root Cause Diagnosis & Resolution for Router Voucher/User Commands:
    1. Critical Bug Discovered: RouterOS API Command Syntax Error
       - Problem: me.legrange.mikrotik.ApiConnection/Parser prepends '=' to each parameter word automatically when transmitting over the socket.
       - The code throughout MikrotikClient was writing commands formatted with leading equals, e.g. "/ip/hotspot/user/add =name=... =password=... =profile=...".
       - This caused the library Parser to interpret the first '=' as an empty parameter ("") with null value, serializing "==" over the wire followed by "=name=...".
       - MikroTik RouterOS rejected every single command with "!trap (unknown parameter / syntax error)".
       - Affected operations: addHotspotUser, addHotspotUsersBatch, removeActiveSession, banMacAddress, addRouterProfile, deleteRouterProfile, updateRouterProfile, resetUserCounters, markUsersAsPrintedOnRouter, renewHotspotUser, and deleteHotspotUsersBatch.
    2. Batch Generation & Deletion Failures:
       - addHotspotUsersBatch and deleteHotspotUsersBatch attempted to create temporary RouterOS scripts ("/system/script/add =name=... =source=..."). The source scripts contained unquoted spaces and semicolons which broke in the API parser, and the subsequent run command passed '=number=name' (RouterOS expects internal ID for 'number').
       - When the script failed, the fallback loop also failed due to the leading '=' syntax bug and swallowed exceptions, returning 'true' while zero users were actually created or deleted on the router.
       - AppRepository then called syncVouchersFromRouter(), which erased newly generated vouchers from Room DB because RouterOS never received them, or reloaded deleted vouchers because RouterOS never deleted them.
    3. Comprehensive Fixes Applied:
       - Stripped invalid leading '=' from all command parameter definitions across MikrotikClient (e.g. "name=$code", "password=$pass", "profile=$profile", ".id=$id", "comment=\"$comment\"").
       - Verified over-the-wire sentence serialization using bytecode test script (TestParser) confirming 100% compliant MikroTik API sentences: '/ip/hotspot/user/add', '=name=...', '=password=...', '=profile=...', '=comment=...'.
       - Re-implemented addHotspotUsersBatch to sequentially execute direct API adds with robust user update fallbacks if an account already exists.
       - Re-implemented deleteHotspotUsersBatch to fetch all matching IDs, drop active sessions on router, purge login cookies, and remove users by '.id' directly.
       - Added 'ensureConnected()' method to auto-reconnect dropped socket connections before attempting mutating router operations (vouchers, profiles, bans, kicks).
       - Fixed startPolling() loop in MainViewModel so that it does not exit permanently on transient connection drops.
       - Successfully compiled Kotlin and built APK: app-debug.apk (23.8 MB). Copied output to 'C:\Users\localhost\Downloads\HotspotManager-debug.apk'.
[2026-09-30 13:15] Bulk Delete Crash Resolution, Performance & RAM Optimization, and GitHub In-App Updates:
    1. Bulk Delete Crash & Router Socket Desynchronization:
       - Root Cause:
         a) RouterOS API commands across MikrotikClient were sending 'numbers=...' instead of native API parameter '.id=...'. RouterOS rejected all batch delete calls with '!trap (expected end of command / unknown parameter)'.
         b) In RawRouterOSConnection, when '!trap' occurred, the parser read the trap sentence but failed to drain the terminating '!done' sentence. This left unread bytes in the TCP socket, completely desynchronizing subsequent commands and causing background polling to throw uncaught exceptions.
         c) In MainViewModel, coroutines launched on viewModelScope lacked try/catch and CoroutineExceptionHandler, crashing the Android app to home screen during bulk delete.
         d) In VouchersScreen, LazyColumn items lacked stable keys ('key = { it.code }'), triggering Compose runtime diffing exceptions during batch deletion.
       - Solutions:
         a) Replaced 'numbers=...' with native RouterOS '.id=...' parameter across all API calls (user removal, profile updates/deletion, counter resets, active session kicks).
         b) Implemented fast batch deletion in MikrotikClient: queried '/ip/hotspot/user/print =.proplist=.id,name' once (~40ms), mapped matching IDs, and deleted in batches of 50 using '.id=*1,*2,...'. Dropped active sessions and cookies cleanly.
         c) Drained terminating '!done' sentence on '!trap' in RawRouterOSConnection, and closed socket on fatal/unhandled errors to prevent desynchronization.
         d) Added CoroutineExceptionHandler to MainViewModel and wrapped all coroutines in try/catch(Throwable).
         e) Added stable keys 'key = { it.code }' to LazyColumn in VouchersScreen.
